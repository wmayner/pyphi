`explain()` on a system result reports the gap to the runner-up partition on the values the minimum partition was chosen on: normalized φ before the intrinsic-information requirement applies. Where the requirement set φₛ, the runner-up used to be lowered by the requirement too, so the gap could be negative and the runner-up could look better than the partition that beat it. The runner-up (`sia.runner_up`) now keeps its values from the comparison, and its `gap` field records the difference; files saved before this change load with `gap = None`, and `explain()` then leaves the gap out. A system partition now prints with the connections it severs (`2 parts: {A,B}; cut A→B`), so partitions into the same parts that sever different connections no longer print the same; an edge cut prints its severed connections instead of their count. The minimum partition, φₛ and every other φ value are unchanged. The documentation now says what the minimum partition is chosen on.
