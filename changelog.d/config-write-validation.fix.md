Every write to `pyphi.config` is now checked against the other options, as `config.override()` and configuration files already were. Before, `pyphi.config["iit.version"] = "IIT_4_0_2023"` was accepted and gave IIT 4.0 (2026) values under a 2023 label, and an unknown version or a measure the version does not define failed only later, inside `analyze()`. Now an item assignment, an attribute assignment, or replacing a layer or the `iit` sub-namespace raises a `ConfigurationError` when the result matches no version of IIT, and leaves the configuration unchanged; the message says how to change options together, and to switch versions it recommends the version's preset or the `formalism=` argument. Assigning to a layer object (`pyphi.config.numerics.precision = 6`) raises a `ConfigurationError` that shows the supported write, instead of `FrozenInstanceError`. A misspelt option suggests the closest real one, every renamed or removed 1.x option in the migration guide's table says what replaced it (when read as well as when written), and a 1.x flat `pyphi_config.yml` lists the new location of each of its options. Snapshots installed in parallel workers are not checked again.
