More configuration values are rejected when they are written instead of failing or being ignored at compute time: an `actual_causation.version` that is not registered, an `actual_causation.alpha_measure` that version does not accept, `parallel_workers = 0`, an unknown `parallel_backend`, a `memory_ceiling_percentage` outside 0 to 100, a per-level parallel mapping whose `parallel` or `progress` is not a bool or whose `chunksize` is not a positive integer (NumPy booleans and integers count, and are stored as Python values), and an empty tie-resolution list. The error for an actual-causation measure no longer recommends the IIT presets. Also rejected at write: a `repr_max_table_rows` that is not a non-negative integer (a bad value used to break printing every result), a negative `memory_ceiling_bytes` (`0` keeps the caches empty, as a campaign shard allowed less than 256 MiB sets it), and a boolean `repr_verbosity`. NumPy booleans and integers are accepted for every scalar infrastructure and numerics option, so `pyphi.config.parallel = np.True_` no longer fails with "must be bool; got bool", nor `pyphi.config.precision = np.int64(10)` with "must be int; got int64".
