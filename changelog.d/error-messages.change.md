Error messages for common first mistakes now say what is wrong and how to fix it. A state-by-state TPM is checked for entries outside [0, 1], NaN and rows that do not sum to 1 before the conditional-independence test, and the error gives the row and its input state; the conditional-independence error links to the page that explains it. An out-of-range TPM entry is reported as entered, with its unit and input state, instead of as a derived probability. `pyphi.analyze`, `pyphi.estimate_analysis` and `pyphi.System` raise a `TypeError` that says what to pass when given a `System` or an array instead of a `Substrate`. A state must be a sequence with one entry per substrate unit (including the background units outside `subset`); a string, dict, scalar or `None` raises a `TypeError`. A subset that is not a sequence, mixes labels with indices or names a unit twice raises an error instead of being reinterpreted. Node labels must be strings. `pyphi.load` explains files it cannot read: a PyPhi 1.x `jsonify` file, a file not saved by `pyphi.save`, malformed data, or a file from a newer version, and gives the path. An unknown unit-function name lists the known ones.

The Analysis card gives a "Why φ_s = 0" row when φ_s is 0 for a structural reason, such as a system that is not strongly connected, and IIT 4.0 null results record the system's current state. The MCP `analyze` summary has a matching `null_reason` key.

`alphabet=` on `Substrate` takes one size per unit as well as a single size. `np.asarray(substrate.tpm)` gives the state-by-node array (one row per input state, little-endian, one column per unit) when every unit is binary, and raises a `TypeError` that points to `.to_pandas()` and `.to_joint()` otherwise. Importing PyPhi in a notebook without ipywidgets no longer prints a `TqdmWarning`, and importing POT no longer shows its `SyntaxWarning`s.
