# Maximal relations and maximal faces — design

**Date:** 2026-07-13
**Status:** Approved in discussion; pending spec review

## Motivation

The degree ≥ 2 relations form a downward-closed family (an abstract simplicial
complex over distinctions): every subset of a relation's relata with at least
two members is itself a relation. Users analyzing relational structure (e.g.
building an atlas of which distinctions co-bind) want the *maximal* elements
of this family — the facets — without enumerating the full, combinatorially
large relation set. The same question exists one level down for relation
faces (sets of causes/effects, in the sense of Albantakis et al. 2023, S3
Appendix).

Both maximality computations turn out to be closed-form over the atom
incidence Z(n) — the set of distinctions whose purview-union contains the
state-tagged unit n — which already exists as
`AnalyticalRelations._atom_index`. No relation enumeration is needed.

## Terminology

- **"Face"** is the IIT 4.0 paper's term (S3 Appendix): a direction
  assignment — the cause, the effect, or both, from each relatum — with
  congruent overlap. This is `RelationFace` in the code.
- **"Maximal"** here always means **maximal under set inclusion** (the
  standard usage over families of sets: maximal simplices, maximal cliques).
  φ_r-ranking is already served by `strongest()`; docstrings cross-reference
  it. Method names use `maximal_*`, not "facet", to avoid reading as
  "maximal `RelationFace`s" at the distinction level.

## Semantics

- **Degree ≥ 2 only.** Self-relations are excluded: the family is *not*
  downward-closed into degree 1 — a self-relation's overlap is a different
  formula (cause ∩ effect within one distinction) and can be empty even when
  the distinction participates in strong degree-2 relations. The S3 Appendix
  treats self-relations separately for the same reason. Isolated
  distinctions remain visible through the membership map (empty tuple).
- **The two levels are computed independently.** A maximal face's parent
  relation need not be a maximal relation: a face can bind an atom that a
  superset relation excludes. Maximal faces are therefore *not* obtainable
  by taking faces of maximal relations; both come from per-atom groups.
- **Filtered sets.** `materialize(min_phi=…, max_degree=…)` breaks downward
  closure, so "facets of a filtered subset" is not a well-defined complex.
  The methods compute facets of the complex *generated by the participating
  distinctions*, and the docstrings say so.

## API surface

Three methods on the `Relations` base class, working on every backend:

```python
def maximal_relations(self) -> ConcreteRelations:
    """The relations maximal under set inclusion of their relata.

    The facets of the relation complex: every relation's relata are a
    subset of some maximal relation's. Degree ≥ 2 only; self-relations
    are excluded. For φ_r-ranked relations see ``strongest()``.
    """

def maximal_faces(self) -> frozenset[RelationFace]:
    """The relation faces maximal under set inclusion of their relata
    (causes/effects), across all relations."""

def maximal_relations_by_distinction(
    self, distinctions
) -> tuple[tuple[Relation, ...], ...]:
    """For each distinction, the maximal relations containing it.

    Parallel to ``distinctions`` (mirroring ``sum_phi_by_distinction``);
    an isolated distinction gets an empty tuple.
    """
```

- `maximal_relations()` returns `ConcreteRelations`, so summary statistics
  (`degree_spectrum()`, `sum_phi()`, `num_relations()`) and export
  (`to_pandas()`) come from the existing query surface. No new stats or
  export methods.
- `maximal_faces()` returns `frozenset[RelationFace]`, matching the type of
  `Relation.faces`. Each face carries the φ_r of the relation it is a face
  of, as faces do today.

## Algorithm

One module-level core, mirroring `all_relations(distinctions)`:

1. Build the atom incidence: for each state-tagged unit n,
   Z(n) = the distinctions whose purview-union contains n. Keep groups of
   size ≥ 2.
2. **Maximal relations** = the maximal elements of the distinct {Z(n)} under
   inclusion, each wrapped as a (lazy) `Relation`. Justification: a set of
   distinctions is a relation iff it lies inside some Z(n), and each Z(n) is
   itself a relation (its overlap contains n; all distinctions have φ > 0).
3. **Maximal faces** = the same construction one level down:
   M(n) = the causes/effects whose purview contains n; the maximal distinct
   M(n) become `RelationFace(M(n), phi=Relation(Z(n)).phi)`. The parents of
   M(n) are exactly Z(n).
4. **Membership map** = a containment check of each input distinction
   against the facet tuple; the facet count is bounded by the atom count.

Cost: O(atoms²) frozenset comparisons, with atoms ≤ units × states. No
relation enumeration anywhere.

### Backends

Backends differ only in where distinctions come from and which atoms count:

| Backend | Distinctions | Atom filter |
|---|---|---|
| `AnalyticalRelations` | `self.distinctions` | all |
| `AnalyticalFoldRelations` | parent distinctions | atoms in the seeds' purview unions |
| `ConcreteRelations` | union of relata over stored relations | all |
| `NullRelations` | none | — (empty results) |

Fold justification: the incident-relations family is not downward-closed,
but every incident relation r contains a seed d and has overlap
o(r) ⊆ pu(d), so for any atom n ∈ o(r), Z(n) ∋ d is itself incident and
contains r. Maximal incident relations are therefore the maximal Z(n) with n
restricted to the seeds' purview unions.

## Display/export adjustments

- `Relation._pandas_record` gains a `purview` column (the sorted overlap
  atoms). Generally useful; the atlas needs which units each facet binds.
  Cost is one cached set-intersection per exported row.
- Fix a latent mislabel in `RelationFace._pandas_record`
  (`pyphi/relations.py:123`): it puts the purview atoms under the key
  `"relata"`, which in `Relation._pandas_record` means mechanism labels.
  Rename the key to `purview`. Grep for consumers of the old key before

## Testing

All φ-computing tests pin `IIT_4_CONFIG` (conftest presets).

- **Brute-force equivalence** (main correctness test): on small example
  networks, enumerate all relations via `all_relations`, do a pairwise
  subset scan, and assert exact equality with `maximal_relations()`. Same
  for faces: enumerate every relation's `.faces`, scan, compare with
  `maximal_faces()`.
- **Asymmetric fixture** (symmetric cases can't catch index/side mix-ups),
  plus a case where a maximal face's parent relation is non-maximal, to lock
  in the independent-computation property. If no stock network exhibits it,
  a small synthetic distinction set does (the pu(C) = {x} construction).
- **Coverage property**: every enumerated relation's relata are a subset of
  some maximal relation; no maximal relation is a proper subset of another.
- **Fold**: materialize the incident relation set concretely, scan, compare
  with `AnalyticalFoldRelations.maximal_relations()`.
- **Membership**: isolated distinction → empty tuple; each listed facet
  actually contains the distinction.
- **Edge cases**: empty/`NullRelations` → empty results; filtered
  `ConcreteRelations` follows the documented generated-complex semantics.
